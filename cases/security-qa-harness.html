Case Study

다수 제품의 반복 품질검사를 위한 QA Harness 구축

DREAM SECURITYQA Senior, 선임연구원2024.10 - Present

반복되는 품질검사 업무 전체를 분석해 처리 방식과 판단 책임을 나누고, 요청건의 입력과 산출물을 연결하는 QA Workflow를 설계했습니다.

Problem

품질검사 요청마다 제출 문서 검토, 원본 결과 표시, Test Case 작성, 제품 테스트, 결과 작성 및 등록이 반복됐습니다. 제품은 달라도 절차에는 공통 작업이 많았고, 전체 품질검사에는 최소 5~7일이 소요됐습니다.

한 단계의 작업을 줄이는 것과 함께, 요청건의 입력과 산출물이 다음 단계로 이어지는 전체 흐름을 개선할 필요가 있었습니다.

Analysis

제품마다 확인할 내용은 다르지만, 품질검사가 진행되는 순서와 산출물을 확인하는 과정은 반복됩니다. 이 공통 흐름을 기준으로 업무를 분해해 자동화 가능한 검증과 제품 Context에 따른 QA 판단을 구분했습니다.

형식, 필수값, 명확한 판정 기준은 정해진 규칙으로 확인할 수 있습니다. 문서의 의미와 요구사항 충족 여부는 제품 맥락을 읽어야 합니다. 단계의 진행과 재검증, 최종 등록 또한 각각 다른 책임으로 다뤄야 한다고 판단했습니다.

QA Strategy

품질검사 전체를 하나의 QA Harness로 묶고, 처리 성격에 따라 역할을 분리했습니다. 자동화 범위를 넓히면서도 QA 판단과 최종 결정의 책임을 명확히 하기 위한 설계입니다.

Code
형식, 필수값, 명확한 판정 기준처럼 결정 가능한 검증을 처리합니다.
Agent
문서 의미와 요구사항 충족 여부처럼 제품 Context가 필요한 판단을 수행합니다.
Orchestrator
단계별 결과에 따라 다음 단계 진행과 재검증을 제어합니다.
Human
최종 등록처럼 중요하거나 되돌리기 어려운 결정을 수행합니다.

Harness Architecture

요청건을 기준으로 각 단계의 입력과 산출물을 연결했습니다. 앞 단계에서 생성한 결과가 검증을 통과하면 다음 단계의 입력으로 이어지고, 최종 등록은 Human이 담당합니다.

Validation

생성된 결과를 그대로 다음 단계에 전달하지 않도록 Generate-Verify 구조를 적용했습니다. 각 단계의 생성 결과를 별도의 검증 역할이 다시 확인하고, Validation Gate를 통과한 경우에만 다음 단계로 진행합니다.

실제 품질검사 요청에서 잘못 생성된 결과 파일 2건을 Gate에서 확인해 다음 단계로 넘어가기 전에 차단했습니다.

Result

39개 제품의 반복 품질검사에 적용할 QA Harness를 설계하고 구축했습니다. 최소 5~7일이 소요되던 전체 품질검사를 약 2~3시간 내 수행 가능한 Workflow로 개선했고, 팀의 실제 품질검사 업무에 활용했습니다.

단계별 Validation Gate로 잘못 생성된 결과 파일 2건을 다음 단계 전에 차단했습니다. 반복 업무를 연결하고 검증하는 구조를 마련해 제품 이해, 변경 영향도 분석, 주요 Risk 검증에 집중할 수 있도록 했습니다.
